## What this is about

If you do not write down an interview, you will misremember it.
Confirmation bias will quietly keep only the parts you liked. The book's
method uses a spreadsheet: one row per question, one column per interview.
This skill gives you the same discipline without the spreadsheet. After
each conversation, give it your raw material — a transcript or hasty notes.
The skill turns this material into a brief, structured debrief file. The
file has one concise answer for each interview question, and honestly
marks the questions you never asked. It also has an addenda section that
lists everything interesting that did not fit a question. The biggest
learning often hides there.

The debrief is short on purpose. It records evidence, not prose. Each
conversation adds one file to a directory. This directory becomes your
record of what real customers actually said. As interviews add up, you
can use these files to update your hypotheses.

## Example invocation

You can invoke the skill like this:

```text
/asb-interview-debrief Here's the transcript from my call with a gym owner
this morning — file it against my QUESTIONS.md.
```

The skill drafts the debrief. It writes one brief answer for each question you asked. It keeps exact phrases from the interview. It honestly marks the questions you skipped. It also adds an addenda section for everything interesting that did not fit a question. The skill asks you to fill gaps the transcript cannot supply — for example, unclear answers or surprises that never made it into your notes.

One practical note: tell the skill where you are working. Name a
directory, or point to your existing files, when you invoke it. The
skill then keeps the method's files together in that location. If you
do not name a location, it asks before it creates anything.
